test(reorg): fork/reorg replay — winning chain 27/27, orphan branch applies

The reorg differential: the simnode builds TWO competing blocks at the
same height (same parent), adds both (2 tips), then mines 3 more blocks
off the current tip — one chain wins, the other orphans.

Results:
- CANONICAL branch (h1-23 + fork B + 3 extensions): 0 failures, final
  state root matches the chain byte-for-byte (c689f624...).
- ORPHAN branch (h1-23 + fork A): the block applies cleanly through the
  Rust state processor — either branch's state transition is valid.

Fixes to the simnode to support this:
- DERO.Fork stores BOTH competing blocks in fork_blocks (Add_Complete_Block
  only persists the canonical side)
- DERO.GetForkBlock serves the orphan-side blocks for the replay

Note: the orphan block has no committed snapshot version, so its embedded
roothash lookup returns garbage — the APPLY is the proof, not the hash.
